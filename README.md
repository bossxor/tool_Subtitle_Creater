# Subtitle Creater (Subtitle_Tool)

영상 여러 개를 고르고 자막 저장 폴더를 지정하면, **음성 인식 → 번역 → 다듬기**까지 자동으로 처리해 자막 파일(`.srt`)을 만들어 주는 Windows 데스크톱 도구입니다.
모든 AI가 **내 PC에서 로컬로** 돌아가므로 API 비용이나 토큰 사용이 없습니다.

> 내 작업물 대시보드: **https://bossxor.github.io/works-dashboard/**

## 주요 기능

- **영상 다중 선택 / 폴더에서 골라 추가**: 폴더를 검색한 뒤 원하는 파일과 작업만 체크합니다. 검색만으로 변환이나 AI 작업이 시작되지 않습니다. 기본은 현재 폴더만 검색하고, 하위 폴더 검색은 직접 선택할 수 있습니다.
  - 새 자막 생성 → 선택한 영상만 대기열에 담고, 시작 버튼으로 실행
  - SMI 형식 변환 → 선택한 `.smi`만 SRT/ASS로 빠르게 변환. AI 검수와 원본 삭제는 각각 선택 사항이며 기본은 끔
  - 인코딩 수정 → 선택한 `.srt`/`.ass`만 BOM 있는 UTF-8로 수정
  - 작업 종류 필터·파일 검색·현재 목록 모두 선택·전체 선택 해제 지원
- **선택한 언어로 번역 + 다듬기**: 앞뒤 문맥과 용어집(인명·고유명사 고정)을 반영합니다.
- **자막 형식 선택**: 기본은 `srt` 하나. `ass`, `smi`도 체크박스로 추가할 수 있습니다. 모든 형식을 BOM 포함 UTF-8로 저장해 곰플레이어 등에서 한글이 깨지지 않게 했습니다.
- **진행 상황 표시**: `smi 변환 N개 중 k개`, `자막생성 N개 중 k개`처럼 단계별 개수와 전체 진행률(%), 가동 시간과 남은 시간(추정)을 보여주고, 끝나면 결과 표(파일별 완료/실패)와 소요 시간을 보여줍니다.
- **편안한 작업 화면**: 초록색 강조와 여백을 적용한 두 열 레이아웃으로 설정과 진행 상황을 함께 확인합니다. 로그와 결과는 탭으로 구분하며, 작은 화면에서는 설정 영역을 스크롤할 수 있습니다.
- **라이트/다크 화면**: 위쪽 `화면 모드` 버튼으로 자동(Windows 설정을 따름) / 라이트 / 다크를 바꿀 수 있습니다.
- **취소 / 이어하기**: 단계별 결과를 캐시에 저장하므로 중간에 멈춰도 완료된 부분은 다시 하지 않습니다.
- **기존 자막 검사·업데이트**: `기존 자막 검사 · 업데이트`에서 SRT/ASS/SMI를 읽기 전용으로 검사합니다. 생성 이력 또는 캐시와 내용이 일치한 파일만 자동 선택합니다. 일본어 원문이 있으면 새 번역을 비교하고 선택한 줄만 적용하며, 원본 백업을 같은 폴더에 남깁니다. 출처 불명·수정된 파일은 자동 선택하지 않습니다.
- **재처리 선택**: `처리 방식`에서 이어하기 / 번역만 다시 / 음성 인식부터 다시를 고릅니다. 기존 자막 검사 창에서 원본 영상을 연결해 재인식 대기열에 추가할 수도 있습니다.
- **덮어쓰기 확인**: 같은 이름의 자막이 이미 있으면 덮어쓸지 물어봅니다.

## 동작 방식

```
영상 ─ ffmpeg(오디오 추출) ─ faster-whisper large-v3(GPU) ─ 문장 단위로 재분할
     ─ TranslateGemma 12B (llama.cpp CUDA)로 줄 단위 번역 ─ 검증/재시도 ─ srt(+ass/smi) 저장
```

- **음성 인식**: [faster-whisper](https://github.com/SYSTRAN/faster-whisper) `large-v3`(빠른 모드 `large-v3-turbo`), 배치 추론 + VAD
- **번역**: 번역 전용 모델 [TranslateGemma 12B](https://huggingface.co/mradermacher/translategemma-12b-it-GGUF) (IQ4_XS, 6.6GB)를 기본으로 사용합니다. 기본 설정의 **번역 품질 → 정밀**에서 [TranslateGemma 27B](https://huggingface.co/mradermacher/translategemma-27b-it-GGUF) (Q4_K_M, 16.5GB)를 선택할 수 있습니다. [llama.cpp](https://github.com/ggml-org/llama.cpp)로 실행하며, 범용 모델(Qwen3-8B)은 smi 변환의 AI 검수에 씁니다.
- **타임스탬프는 코드가 관리**하고 LLM에는 텍스트만 전달해서 싱크가 어긋나지 않게 했습니다.
- 번역 결과를 검증하고 문제가 있는 줄은 다시 번역합니다. 끝내 처리하지 못한 줄은 원문을 유지하고 작업 로그에 남깁니다.
- 번역은 가까운 앞뒤 일본어 대사를 참고하고 현재 줄만 출력합니다. 기존 말투 힌트와 문맥을 함께 사용하며, 재시도에서는 문맥을 빼 잘못된 결과의 반복을 줄입니다. 영어 안내문·빈 결과·알려진 번역 거절문을 성공 처리하지 않습니다. 일반 문장의 무조건적인 가나 음역은 하지 않습니다.
- 미번역·제한적 소리 음역은 캐시에도 상태를 저장하며 결과 표에서 `일부 미번역`·`검토 필요`로 구분합니다. 이 상태는 의미 정확도 점수가 아닙니다.

자세한 설계 근거와 실측 수치는 [`DESIGN.md`](DESIGN.md)에 있습니다.

## 실측 성능 (RTX 3070 Ti 8GB 기준)

| 단계 | 결과 |
|---|---|
| 음성 인식 (large-v3, 기본) | 10분 오디오 약 17초 (빠른 모드 large-v3-turbo는 약 6초) |
| 번역 (TranslateGemma 12B IQ4_XS, 4개 병렬) | 40줄에 약 20~24초 (1시간 영상 약 7분 예상) |

> 테스트에는 일본어 낭독 샘플과 대사를 사용했습니다. 음성 인식 수치는 CC0 낭독 샘플로 잰 값입니다. 배경음악·겹치는 대사가 있는 실제 드라마에서는 달라질 수 있습니다.
>
> **번역 정확도**: 일상 대사 40줄(제가 기준 번역을 쓰고 채점한 소규모 평가)에서 뜻이 틀린 줄이 Qwen3-8B는 약 10줄, TranslateGemma 12B는 1~4줄이었습니다. 음성 인식 오류는 이 평가에 포함되지 않았습니다. 대신 영상마다 작업 로그에 음성 인식 확신도를 남겨서, 번역이 이상할 때 원인이 인식인지 번역인지 가릴 수 있게 했습니다. 자세한 내용은 [`DESIGN.md`](DESIGN.md)를 참고하세요.

## 요구 사항

- Windows 10/11 (현재 Windows 전용)
- NVIDIA GPU (VRAM 8GB 이상 권장) + 최신 드라이버
- **ffmpeg**가 PATH에 있어야 합니다 (`winget install Gyan.FFmpeg`)
- Python 3.11 (소스로 실행/빌드할 때)
- 첫 실행 때 필요한 모델·런타임을 자동으로 내려받습니다 (기본 설정 기준 약 10GB: 음성 인식 모델 2.9GB + 번역 모델 6.6GB + llama.cpp). smi를 AI로 검수하며 변환할 때만 Qwen3-8B(4.7GB)를 추가로 받습니다.
- 번역 모델은 Gemma 이용 약관(license: gemma)의 적용을 받습니다.

## 실행 방법

### 소스로 실행

```bash
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe main.py
```

처음 "자막 생성 시작"을 누르면 필요한 파일이 없을 때 내려받을지 물어봅니다.

### CLI로 실행

```bash
.venv\Scripts\python.exe -m core.cli --videos a.mp4 b.mp4 --out-dir D:\subs
```

### exe로 빌드

```bash
.venv\Scripts\python.exe build_exe.py
```

`dist/Subtitle_Tool/Subtitle_Tool.exe`가 만들어집니다 (PyInstaller onedir). 모델(`models/`)과 llama.cpp(`tools/llama.cpp/`)는 용량 때문에 exe에 포함하지 않고, exe 옆 폴더에서 찾거나 첫 실행 때 내려받습니다.

## 설정

`config.yaml`에서 STT 정밀도, 번역 배치 크기, 자막 줄 길이/표시 시간, 출력 형식과 인코딩 등을 바꿀 수 있습니다. 대부분은 GUI 옵션으로도 조절되며, GUI를 열 때 이 설정을 반영합니다.

캐시는 입력 파일의 크기·수정 시각과 단계별 설정을 함께 확인합니다. 용어집, 번역 모델, 언어, 음성 인식 정밀도 또는 구간 설정을 바꾸면 해당 결과를 다시 계산합니다. 이전 버전 캐시는 삭제하지 않지만, 새 기준의 정보가 없으므로 업데이트 후 첫 실행에서는 다시 계산합니다. 이후 동일 조건에서는 새 캐시를 재사용하며, 음성 인식 캐시가 있으면 오디오 재추출도 건너뜁니다.

## 알려진 한계

- 새로 생성하는 자막 옆에는 `.subtitle-tool.json` 생성 이력이 저장됩니다. 지우면 자동 출처 판정이나 원문 연결을 잃을 수 있습니다. 과거 파일은 캐시 내용 일치로 확인하며, 파일명만으로 판정하지 않습니다. 변경 적용과 재생성 덮어쓰기는 `.backup-날짜-식별자` 원본 백업을 남깁니다.
- 일본어 원문·영상이 없는 한국어 자막은 문자·형식 검사만 가능합니다. 스타일 태그나 다국어 구조를 안전하게 보존할 수 없는 파일은 읽기 전용입니다. 검사에서 이상이 없다는 표시는 의미 정확도를 보장하지 않습니다.
- 현재 설치된 Kotoba v2 변환 모델에는 디코더와 맞지 않는 단어 정렬 설정이 있습니다. 이 조합은 네이티브 충돌 대신 명확한 오류로 중단합니다. 기본 large-v3를 유지합니다.

- 이 도구를 만든 PC(개발 환경)에서만 검증했습니다. 모델이 하나도 없는 깨끗한 PC에서 첫 실행 다운로드 전체 흐름은 아직 검증하지 못했습니다.
- 실제 드라마(배경음악, 다중 화자, 겹치는 대사)로는 아직 충분히 검증하지 못했습니다.
- 다른 프로그램(게임, 브라우저, 배경화면 프로그램 등)이 GPU 메모리를 많이 쓰면 번역이 느려집니다. 번역 서버가 남은 GPU 메모리에 맞춰 자리를 잡고, 응답이 없으면 자동으로 다시 시작하지만 작업 중에는 GPU를 많이 쓰는 프로그램을 끄는 것이 좋습니다.
- 고유명사·고어체 등은 번역 검증을 통과하지 못해 원문이 그대로 남을 수 있습니다. 그 비율은 영상에 따라 달라지며 작업 로그에 남깁니다.
- smi → srt 변환 시 AI 검수는 깨진 글자를 복원하지만, 정말로 복구 불가능한 손상은 그럴듯한 다른 내용을 만들어 낼 수 있습니다. (일반적인 인코딩 문제는 자동 인코딩 감지가 먼저 결정론적으로 고칩니다.)
- 문장이 너무 길면 시간을 나누지 않고 2줄 줄바꿈만 합니다.

## 음성 트랙 선택

원본 언어가 일본어이면 `ja`/`jpn`으로 표시된 음성 트랙을 우선 사용합니다. 여러 일본어 트랙에서는 해설 트랙보다 일반 대사를 우선합니다. 언어 표시가 없으면 기본 음성 트랙을 사용하고 로그에 남깁니다.

이전 버전에서 다른 언어의 트랙을 추출했을 가능성이 있어, 이전 WAV/음성 인식 캐시는 새 처리에서 재사용하지 않습니다. 기존 자막 파일은 자동으로 일괄 변경하지 않습니다.

## 품질을 우선할 때

- **번역 품질 → 정밀**: 27B 모델을 사용합니다. 첫 선택 시 16.5GB를 받으며 시스템 메모리 32GB 이상을 권장합니다. 8GB GPU에서는 CPU를 함께 쓰므로 느립니다. 고정 대사 32줄 CPU 비교에서는 약 366초로, 표준 12B의 115초보다 약 3배 오래 걸렸습니다. 실제 속도는 GPU 여유와 문맥 길이에 따라 달라집니다.
- 이 비교에서 관용구, 청유형, 일부 존대 표현은 개선됐지만 `ますます困る`를 짜증으로 과장하는 오류도 생겼습니다. 정밀 모드도 의미·말투를 보장하지 않습니다. 비교 근거와 남은 한계는 [품질 측정 기록](docs/superpowers/plans/2026-11-08-quality-measurements.md)을 참고하세요.
- **용어집**에 등장인물 이름의 일본어 표기를 넣으면 음성 인식에도 참고합니다. 번역 고정 값은 번역에 사용합니다. 이름 목록이 바뀌면 음성 인식 캐시도 새로 계산합니다.
- 기존 영상은 **번역만 다시** 또는 **음성 인식부터 다시**를 선택할 수 있습니다. 기존 자막 검사에서는 변경할 줄만 비교·적용하고 원본 백업을 남깁니다.

반복 압축은 의미 없는 소리에만 적용합니다. 금액·번호·반복 대사를 줄이지 않으며, 완결된 감탄사나 긴 침묵을 넘겨 자막을 합치지 않습니다. 모델 응답이 중간에 잘리면 완료된 번역으로 쓰지 않습니다.
