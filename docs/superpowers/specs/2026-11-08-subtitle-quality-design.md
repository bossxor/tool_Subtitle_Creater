# 자막 품질 복구와 안전한 업데이트 — 설계 초안

날짜: 2026-11-08
상태: 사용자 검토 전. 아래 구현 선택은 제안이며 아직 합의된 것으로 취급하지 않는다.

## 목적

일본어 영상에서 실제로 읽을 수 있는 자연스러운 한국어 자막을 만든다. 사용자는 딱딱하고 고정적인 말투와 음성 인식 품질 때문에 결과를 사용할 수 없다고 말했다. 외관 개선보다 받아쓰기·내용·말투·타이밍을 우선한다. 문제 영상이나 시간대를 사용자가 직접 찾아 제공해야 하는 흐름을 만들지 않는다.

기존 Python/PySide6, 로컬 GPU 실행, 설치된 모델과 의존성을 유지하는 것은 구현자의 제안이다. 기존 생성 자막만 선택해 업데이트하고, 외부에서 받은 자막은 자동 변경하지 않는 요구를 유지한다.

## 접근 방식

1. **인식부터 번역까지 품질 경로 복구 — 추천.** 보유 음성 샘플과 캐시로 인식·구간 분할·문맥 번역·검증을 따로 확인한다. 실제 원문 오류와 번역 오류를 구분할 수 있지만 번역만 바꾸는 것보다 작업량이 크다.
2. **번역만 교체.** 기존 인식 캐시로 빠르게 개선할 수 있지만 누락되거나 잘못 받아쓴 대사는 복구하지 못한다. 사용자의 '기본에 충실' 요구를 충족하지 못하므로 우선안으로 추천하지 않는다.
3. **새 대형 모델 또는 외부 API로 전환.** 비용·메모리·서비스 의존성이 바뀌고 현재 검증 결함은 그대로 남는다. 비교 증거 없이 기본 경로로 채택하지 않는다.

이 문서는 1번의 구체안이다. 사용자는 아직 접근 방식과 문서에 대한 최종 승인을 하지 않았다.

## 성공 기준과 범위

- 영어 안내문·번역 거절문·빈 결과를 번역 성공으로 처리하지 않는다.
- 정상 약어·고유명사를 포함한 한국어 자막은 허용한다. 단순히 영문자를 전부 지우지 않는다.
- 히라가나 문장 전체를 발음으로 바꿔 성공했다고 표시하지 않는다.
- 짧은 조각을 독립된 완전 문장인 것처럼 번역하지 않고 주변 원문을 참조한다.
- 자막의 원뜻·생략·말투를 보존한다. 모든 문장을 반말이나 존댓말로 통일하지 않는다.
- 실제 실패와 검토 필요 상태가 캐시, 작업 로그, GUI에 남는다.
- 기존 파일은 검사·미리보기까지 읽기 전용이다. 사용자가 선택한 변경만 적용하고 기존 파일은 백업한다.
- 모델·프롬프트 변경의 효과를 고정된 입력의 전후 비교로 제시한다. 정답 없는 확신도나 단일 낭독 샘플을 전체 정확도로 발표하지 않는다.

## 1단계: 재현 가능한 기준 마련

현재 진단 산출물 `bench/out/quality_audit*.json`에서 개인정보·영상 파일명을 제외한 최소 회귀 사례를 `bench/`의 추적되는 테스트 자료로 옮긴다. 원문 조각, 영어 안내문, 한국어 설명문, 약어 포함 원문, 빈 응답, 지속 실패를 포함한다. 모델 고정 응답 테스트와 실제 모델 평가를 분리한다.

번역 평가는 인사·생략된 주어·관용구·정중체/친근한 대화·이름·짧은 조각에 대해 '보존할 의미, 허용할 표현, 없어야 할 추가 의미'를 기록한다. 한 문구와 문자열이 일치해야 통과하는 평가로 만들지 않는다. 합성 대화는 평가용으로 명시한다.

사용 가능한 낭독 샘플은 인식 비교와 타임스탬프 안정성 검사에 사용한다. 출처가 확실한 정답 대본을 구할 수 있는 구간만 CER를 계산하고, 없는 구간은 비교 자료로만 사용한다. 사용자가 사례를 주지 않았다는 이유로 작업을 중단하지 않는다. 캐시만으로 음성 인식 정답을 입증했다고 주장하지 않는다.

## 2단계: 인식과 구간 분할

large-v3를 유지한다. 정확 모드에서 순차 인식 beam 5와 현재 배치 인식 beam 1을 같은 입력으로 비교한다. 비교용 실행은 제품 동작과 분리하고 워밍업·모델 로딩·추론 시간을 구분한다.

**기본값 변경 조건:** 정답이 확보된 구간의 문자 오류율이 줄고, 무음 환각·누락·시간 역전이 증가하지 않아야 한다. 정답을 확보하지 못하거나 개선이 입증되지 않으면 정확 모드의 인식 경로는 그대로 두고, 비교 결과와 미검증 항목을 남긴다. beam 증가만으로 품질 개선을 주장하지 않는다. 이 조건 안에서 실험 실행 방법은 구현자에게 맡긴다.

인식에서 얻은 구간 경계를 유지할 수 있도록 필요한 최소 정보만 보존한다. 짧은 일본어 조각과 정상 감탄사를 글자 수만으로 합치거나 삭제하지 않는다. 구간 분할 변경은 실제 인식 구간·침묵·문장 경계에 근거하고 긴 침묵을 넘어 합치지 않는 회귀 사례로 검증한다. 의미 있는 반복 대사를 중복이라는 이유만으로 잃지 않는지도 확인한다.

## 3단계: 문맥과 말투를 반영한 번역

TranslateGemma 기본 경로에 현재 cue 앞뒤의 일본어 원문을 참고 문맥으로 제공한다. 출력 대상은 현재 cue 하나로 한정해 ID·시간 대응을 유지한다. `llm.context_sentences`를 활용하고 참조 원문에 포함된 지시문은 번역 지시로 취급하지 않는다.

기존 일본어 어미 기반 반말 지시는 보조 힌트일 뿐 확정 규칙이 아니다. 주변 표현과 대사 어조를 먼저 보존하고 없는 호칭·주어·감정·사정을 추가하지 않도록 한다. 화자 분리 없이 관계를 알아냈다고 가정하지 않는다.

**채택 조건:** 고정한 대화 평가에서 의미·말투가 개선되고, 참고 문맥이 출력에 섞이거나 cue 대응이 틀어지는 회귀가 없어야 한다. 평가셋과 각 항목의 의미·말투 체크리스트를 변경 전에 확정하고, 구현자가 같은 입력의 전후 출력을 그 기준으로 검토해 항목별 근거를 기록한다. 중요한 의미 반전·없는 내용 추가·참고 문맥 누출은 새로 발생하면 안 되며, 체크리스트 위반 수가 줄어야 채택한다. 이를 객관적인 전체 번역 정확도로 표현하지 않는다. 문맥 프롬프트가 악화시키면 채택하지 않는다. 먼저 검증·실패 처리는 독립적으로 적용한다. 더 큰 모델로의 교체는 이 문서의 필수 조건이 아니다.

## 4단계: 검증·실패·캐시·결과 표시

`core/validate.py`에 목적 언어를 고려한 공통 번역 검증을 두고 JSON/TranslateGemma 양쪽에서 사용한다. `verify_cues()`의 인코딩 검수는 별도 목적이므로 번역용 제한을 그대로 적용하지 않는다. 한국어 출력에서는 일본 문자 잔존, 공백, 잘못된 자료형, 원문에 없는 영어 본문, 알려진 안내·거절문을 검사한다. 짧은 정상 감탄사·숫자·기호·원문 약어는 별도 사례로 보존한다.

재시도 소진 뒤 영어 결과를 채택하는 경로는 제거한다. 실패한 일반 가나 문장을 무조건 음역하지 않는다. 복구할 수 없으면 기존 원문 보존 정책을 유지하고 명확히 '미번역'으로 보고한다. 소리만 있는 감탄사의 결정론적 음역은 의미 문장과 구분해 제한적으로 적용하며 '음역' 상태를 남긴다.

`TranslateReport`를 확장하거나 같은 역할의 기존 자료 구조를 활용해 미번역·음역·검토 필요 상태를 전달한다. 번역 캐시에 상태와 번역 알고리즘 버전을 함께 저장한다. 기존 캐시는 삭제하지 않고 새 버전에서 재번역하거나 검사 대상으로만 활용한다. 인식 결과까지 불필요하게 폐기하지 않는다.

동일 포트에 다른 모델 서버가 있으면 모델을 확인하고, 일치하지 않으면 다른 모델로 처리하지 않는다. 소유하지 않은 프로세스를 종료하지 않는다.

## 5단계: 생성 이력과 선택 업데이트

새로 생성하는 파일은 출력 위치·출력 내용 해시·원본 영상 식별자·언어·모델/번역 버전·관련 캐시를 로컬 생성 이력에 기록한다. 이력 기록 실패는 사용자에게 알리되 이미 생성한 자막을 삭제하지 않는다.

과거 자막은 출력 파일과 캐시로 재구성한 결과의 내용 일치 및 경로·작업 이력을 대조한다. 비교로 확인된 파일, 이력만 있어 추정되는 파일, 출처 불명을 구분한다. 이름만 같다는 이유로 툴 생성분으로 판정하지 않는다. 이력이 있지만 내용 해시가 달라진 파일은 수정됨으로 표시한다. 자동 후보 선택은 확인된 생성분만 허용한다.

사용자가 직접 선택한 기존 자막은 출처와 무관하게 읽기 전용 검사할 수 있다. 원문 인식 캐시가 유효하면 번역만 다시 수행한다. 인식을 다시 하려면 원본 영상이 필요하며 별도 선택으로 실행한다. 한국어 자막만 있는 경우 형식·문자·인코딩 검사는 가능하지만 원문 의미 검증·재번역이 가능하다고 표시하지 않는다.

새 결과는 별도 임시 결과로 만들고 변경 비교에 제공한다. 적용은 선택한 파일만 대상으로 하고 기존 파일의 고유 백업을 보존한다. 쓰기는 임시 파일 생성 후 교체로 완료하며 실패 시 기존 파일을 유지한다. 취소는 아직 적용하지 않은 파일을 변경하지 않는다.

구현자의 범위 결정:

- 영상 없이도 SRT/ASS/SMI 파일을 직접 선택하거나 폴더에서 찾아 검사할 수 있다. 기존 SMI 파서와 인코딩 감지를 활용하고 SRT/ASS 읽기만 최소한으로 보완한다.
- `번역만 다시`는 현재 파일의 시간·cue 순서를 유지하고 텍스트만 후보로 만든다. 원문 캐시와 cue가 안전하게 대응하지 않으면 이 작업을 비활성화하고 '전체 재생성 필요'로 표시한다. 추정으로 다른 줄의 원문을 끼워 맞추지 않는다.
- `음성 인식부터 다시`는 영상을 기준으로 cue와 시간을 새로 만드는 작업이며, 기존 파일 변경 비교에 시간 차이도 표시한다. 텍스트 교정과 전체 재생성을 같은 작업으로 숨기지 않는다.
- 이 툴이 만드는 일반 SRT, 단일 텍스트 언어의 SMI, 일반 Dialogue 이벤트 ASS를 업데이트 대상으로 지원한다. ASS의 비대사 헤더·스타일·이벤트 필드와 텍스트 안의 표현 태그는 보존한다. 태그와 텍스트 대응을 보존할 수 없거나 다국어 SMI 등 지원 범위를 벗어나면 읽기 전용 검사와 별도 SRT 후보 내보내기만 허용한다. 원본 형식을 단순화해 덮어쓰지 않는다.
- 수동 수정 이력이 있거나 생성 여부가 추정인 파일은 자동 선택하지 않는다. 사용자가 직접 선택한 파일도 미리보기와 적용 시 현재 내용 해시를 다시 확인해 검사 이후의 편집을 덮어쓰지 않는다.

## UI/UX

기존 화면의 테마와 위젯을 재사용한다. 장식·새 디자인 시스템보다 작업 선택과 상태 이해를 개선한다.

- 작업 종류: 새 자막 생성 / 기존 자막 검사·업데이트.
- 기존 파일 목록: 출처 판정, 원문/영상 확보 여부, 문제 수, 선택할 작업, 결과 상태.
- 검사 결과: 해당 줄의 원문·현재 자막·후보 번역·문제 사유·시간. 문제 구간을 사용자가 처음부터 찾아내게 하지 않는다.
- 재처리: 번역만 다시 / 음성 인식부터 다시. 필요한 입력이 없으면 이유와 가능한 작업을 표시한다.
- 실행 결과: 완료 / 검토 필요 / 일부 미번역 / 실패 / 취소를 구분한다. 파일 생성 성공을 번역 품질 보증으로 표시하지 않는다.
- 변경 적용: 선택 항목 미리보기, 백업 위치 표시, 선택 적용. 검색과 검사만으로 기존 자막을 바꾸지 않는다.
- 키보드 조작·보이는 포커스·텍스트 상태 표시·백그라운드 실행·취소를 유지한다. 라이트·다크와 기존 최소 창 크기에서 확인한다.

## 영향 범위

핵심: `core/stt.py`, `segmenter.py`, `translate_gemma.py`, `translate.py`, `validate.py`, `pipeline.py`, `llm.py`, `writers.py`, `folder_scan.py`, `worklog.py`, `config.yaml`.

호출부: `core/cli.py`, `gui/worker.py`, `gui/folder_worker.py`, `gui/folder_picker.py`, `gui/main_window.py`. 실제 호출과 반환값을 검색한 뒤 필요한 파일만 수정한다. 새 생성 이력·기존 자막 처리는 기존 모듈에 억지로 섞지 않되, 기능당 불필요한 추상화는 만들지 않는다.

테스트·문서: `bench/textfix_test.py`, `regression_test.py`, `folder_selection_test.py`, 필요한 최소 품질 회귀 테스트/평가 자료, README의 문맥·업데이트·한계 설명. CLI에서도 새 캐시/보고 구조와 취소·이어하기가 유지되어야 한다.

## 순서와 비목표

품질 기준 고정 → 검증·실패 보고 → 인식/문맥 번역 비교와 입증된 변경 → 생성 이력·선택 업데이트 → UI 전체 흐름 확인 순으로 진행한다. 원본 자막의 대량 갱신은 구현 검증과 분리하며 자동으로 수행하지 않는다.

이번 범위에서 외부 API, 새 의존성, 화자 분리, 무조건적인 모델 대형화, 전면적인 화면 재디자인은 하지 않는다. 실제 영상 정답 자료 부족으로 모든 장르의 번역 품질을 입증할 수 없다는 한계는 남는다. 모델 표현의 자연스러움은 문자 검증만으로 보장할 수 없으므로 실제 추론 전후 사례도 함께 검토한다.
